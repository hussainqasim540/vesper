# Vesper

An original game frontend for the R36S (RK3326, 640x480) under Lume, for
GBA, GBC and Nintendo DS, with switchable layouts for the DS's two screens.
Written in C, with DSperate's DS core to be built in (GPL-3.0-or-later).

The plan and its sources: [`docs/0001-feasibility-and-architecture.md`](docs/0001-feasibility-and-architecture.md)
and [`docs/research-ds-feasibility.md`](docs/research-ds-feasibility.md).

## Status

Milestone 1, the skeleton:

- KMS/DRM, GBM, EGL and GLES2 on Panfrost, with page flips on vblank.
- evdev input, every device kept open; ALSA sound from its own thread,
  resampled to 48 kHz with dynamic rate control.
- The shelf over the background, in QuisLab's palette and Inter.
- GBA and GB/GBC through libretro cores: gpSP for GBA (mGBA if gpSP is
  missing), Gambatte for GB/GBC (mGBA if missing). Battery saves are
  written every 10 s when they change, and on leaving the game.
- DS games show on the shelf; they start with milestone 3 (DSperate).

**Checked so far:** the host tests (158 checks, ASan and UBSan, with clang on the Mac and gcc in Linux), the
aarch64 build against Lume's userland, gpSP and mGBA running a GBA game
through Vesper's libretro host on that userland (picture, audio samples and input; not ALSA output),
Vesper's own gpSP and Gambatte builds running a GBA game and a GBC test
ROM the same way, and screenshots of the shelf and a game drawn by the same GLES code with
Mesa's software renderer, and Lume's init starting it (r36s-lightos's
`tools/test_init_stages.sh`, case realvesper). **Not yet checked on the
console.**

## Buttons

| Where | Button | Does |
|---|---|---|
| Shelf | D-pad or left stick | Choose a game |
| Shelf | L1/R1, left/right | A page up or down |
| Shelf | A | Play |
| Shelf | START or POWER | Power off, restart |
| Game | FN | Save and back to the shelf |
| Game | POWER | Save, then the power menu |
| Anywhere | Volume +/- | Volume, in 10% steps |

## Build

Needs Docker (Colima) and Lume's Buildroot output, the `lightos-buildroot`
volume that `r36s-lightos/tools/build_rootfs.sh` fills. It is mounted
read-only.

```bash
tools/build.sh                  # build/aarch64/vesper, for the console
tools/build_cores.sh            # build/cores: gpSP and Gambatte from upstream
tools/build.sh test             # the host tests, in Linux
tools/screenshot.sh ROM CORE.so # build/shots/*.png, no console needed
tools/dist.sh --background IMAGE   # build/card/vesper, with build/cores
```

On the Mac the tests also run natively:

```bash
cmake -S . -B build/host -DVESPER_TESTS=ON && cmake --build build/host && build/host/vesper_tests
```

`tools/build_cores.sh` clones gpSP and Gambatte from libretro at pinned
commits and builds them with Lume's toolchain for the Cortex-A35 (gpSP with
its ARMv8 dynarec). Both are GPL-2.0 and stay separate `.so` files; their
licences and sources go into `cores/` with them. mGBA is not built yet: it
is only the fallback.

`src/font_data.h` is generated by `tools/make_font.py` from Inter, and
committed. The background is not committed (its licence for redistribution
is unknown): `tools/make_background.py` makes it from the wallpaper.

Two tools in the binary itself:

- `vesper --headless CORE.so ROM [FRAMES] [DUMP]` runs a core with no
  display or sound and reports the time per frame: the CPU cost of a core on
  the console, without the 60 Hz pacing.
- `vesper --screenshot OUT.ppm [shelf|power|game [FRAMES]]` draws one screen
  into a pbuffer (Mesa surfaceless).

## On the card

```
vesper/
  bin/vesper                  the program
  cores/*_libretro.so         gpsp, mgba, gambatte
  games/                      ROMs (.gba .gbc .gb .nds), also in subfolders
  games-dirs.txt              more ROM folders, one a line (optional)
  saves/                      battery saves (.sav), one per ROM
  system/                     BIOS files, for the cores that use them
  assets/background.vimg      the background
```

`games-dirs.txt` lets Vesper share another frontend's ROMs on a small card,
for example a line `/flash/slot/Games`. Saves stay in Vesper's own `saves/`.

`VESPER_ROOT` overrides the folder; otherwise it is the parent of `bin/`.
Logs go to stderr, with a `pace:` line every 10 s (frames, late frames).

**Under Lume** (r36s-lightos 231c456 and later): copy `build/card/vesper`
to the root of the card's FAT partition and write `vesper` in
`lightos/frontend`; without that file Lume starts slot. Lume gives Vesper
`VESPER_ROOT=/flash/vesper`, `HOME=/tmp` and its `poweroff`/`reboot`
shims, which end Vesper: it calls them from its own process after saving
and `sync`. Its log is `vesper/logs/vesper.log`, and in the boot's logs.
